# 研究方法、成本与产业链



### 1. 先分清优化了哪一层

| 层次 | 2026 年例子 | 实际改变什么 | 不能据此推出什么 |
| --- | --- | --- | --- |
| 底座/连接架构 | Kimi K3 的 KDA/AttnRes；DeepSeek V4.1 的 CED；Qwen Flash-Next | 信息流、读入/生成计算路径、长序列复杂度 | 只凭结构名称就断定业务效果领先 |
| 预训练与模态 | 图文联合训练、视觉编码器、语音 Thinker/Talker | 模型能接收的信息与训练覆盖 | 看图理解等于原生生成视频；所有“原生多模态”实现相同 |
| 后训练与 RL | K2.7 Code、V4-Flash-0731、长程环境训练 | 工具选择、失败恢复、任务策略、约束遵循 | 必然用了更大底座；奖励更强必然产品更稳 |
| 推理与服务 | KV 压缩、缓存、投机解码、高速服务、batch | TTFT、解码速度、吞吐、存储与费用 | 每 token 更快等于完整任务同比更快 |
| 运行框架与工具 | Swarm、Hosted Agents、搜索/文件接口、Codex 等 harness | 工具权限、记忆、任务分解、重试、验证 | 每个新产品就是一个新基础模型 |
| 发行与治理 | Preview/GA、权重、许可证、准入、退役/路由 | 谁能用、何时能用、能怎样部署与复现 | 开放权重等于无条件商用；API 名称固定等于底座固定 |

### 2. MoE、线性/稀疏注意力和缓存分别解决什么

**MoE 减少每个 token 选择执行的专家计算；不自动删除未激活专家的权重。** 例如 Qwen3.8 开放旗舰标明 2.4T 总参数、95B 激活。仅作量级演示，若全部以 BF16 保存，裸权重约为 2.4×10¹²×2 字节 = **4.8 TB（十进制）**；4-bit 理想裸权重约 1.2 TB。还没计量化元数据、激活、KV、通信缓冲、冗余和并发，也没保证所有模块均可同精度量化。这是算术示例，不是实际部署方案。[模型卡](https://huggingface.co/Qwen/Qwen3.8-2.4T-A95B)

**线性/混合注意力用压缩状态保存部分历史；稀疏注意力只精读被选中的位置；KV 压缩减少保留的历史表示。** 三者可以组合，但可能影响精确检索、跨文件依赖和多模态信息保持。Kimi K3 的混合层、Qwen Flash-Next 的 GDN+QSA、DeepSeek V4.1 的 CED/CSA2 各自组合不同，不能只按“线性”或“稀疏”两个字视为同一种实现。[K3 技术说明](https://www.kimi.ai/blog/kimi-k3)、[Flash-Next 论文](https://arxiv.org/abs/2608.30320)、[V4.1 论文](https://arxiv.org/abs/2609.19969)

**1M 输入窗口、1M 输出预算、永久记忆、长程任务不是一个指标。** 前者是请求容量，输出预算限制生成规模，记忆依赖持久化/检索与上下文管理，长程任务还涉及计划与错误恢复。能读入一百万 token，不证明能同样可靠地处理所有位置的关系；运行十小时，也不证明十小时都在有效工作。Gemini4 Argon 的公告尤其要留意：其 1M 是输出上限这一项，不能抄成输入首创。[Argon 公告](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-argon/)

### 3. 更长思考和更多 Agent 都有预算

推理时扩展可以增加候选、验证和纠错机会，同时增加生成、工具调用和等待。多 Agent 可以并行缩短关键路径；总计算与费用可能上升。GPT-5.6 ultra 默认多代理、Kimi Swarm 的高并发演示，应和单代理、同预算结果分开。模型能调用多少次工具不如“在允许的成本/时限内，多少任务验收通过”有解释力。[GPT-5.6 方法脚注](https://openai.com/index/gpt-5-6/)、[Kimi Swarm](https://www.kimi.com/en/blog/agent-swarm)

保留历史思考有助多轮状态连续，但也可能累积错误状态与上下文费用；让模型自检并不保证检验器独立可靠。应记录重复调用、无效工具调用、长尾超时、人工接管和回滚。小米 9 月的工具重复反思是重要反证：只奖励结果正确，可能没有惩罚过程浪费；局部问题样本的复现率又不能当全体用户的发生率。[官方复盘](https://mimo.xiaomi.com/blog/mimo-v2-6-tool-call-repetition)


## 跨厂商比较：哪些结论现在可以下，哪些不可以

**可以下的结论**：公开发布已从聊天/短题向代码仓库、文档、浏览器、专业工作与长程工具链迁移；架构效率、后训练和运行框架都在贡献体验。**不能下的结论**：某家在一张厂商表中多数格领先，就全面领先所有行业研究任务；开放旗舰已经让昂贵算力或人工核验不再重要。

### 有独立证据，也必须限定范围

NIST/CAISI 于 7 月 17 日发布 GLM-5.2 独立评估，综合与网络安全能力分别使用其自有评测集合比较，并报告不确定性和防护差异。这个例子说明应区分“厂商某项 SOTA”与“独立综合测评”：不同任务集合可以形成不同排序。它不是 11 月所有模型的实时总榜，也不能外推任何特定中文行业研究质量。[CAISI 原文与完整报告入口](https://www.nist.gov/news-events/news/2026/07/caisi-assessment-zais-glm-52)

SWE-bench 官方默认 Verified/Bash Only 页面强调同一 mini-SWE-agent 环境，且标识团队直接运行或检查的结果；该条件比跨厂商各选最优 harness 的营销表更有可比性。但它仍只覆盖给定软件任务。Artificial Analysis 的综合指数也是有版本、权重和语言覆盖边界的评测，不是人类所有工作的通用智力刻度。[SWE-bench 方法与榜单](https://www.swebench.com/)、[Artificial Analysis 方法](https://artificialanalysis.ai/methodology/intelligence-benchmarking)

### 一个分数至少附这八个字段

| 字段 | 要核实什么 | 典型误读 |
| --- | --- | --- |
| 模型身份 | 快照、路由、思考档、量化、供应商 | 把相同 API 别名的两次结果当同一模型 |
| 测试集 | 名称、版本、子集、题量、时间范围 | Terminal-Bench 2/3/4 直接画成进步曲线 |
| 指标定义 | pass@1、pass@k、平均分、严格成功/部分完成 | 将多次尝试最好结果与一次成功率比较 |
| 环境 | harness、提示词、工具、网络与文件权限 | 把工具与框架优势全归模型参数 |
| 预算 | 输出/思考 token、工具次数、超时、并行代理 | 用无限预算成绩对比默认服务 |
| 数据污染 | 时间切分、私有题、去污染办法、训练可见性 | “公开题分数高”自动证明真实泛化 |
| 判定 | 单元测试、人工/模型裁判、盲法、失败处理 | 展示案例替代有分母的统计 |
| 经济性 | 所有尝试总费用、延迟分布、验收标准 | 只报成功样本速度，忽略失败与人工返工 |

百分点和相对增长也要分清：成功率 50%→60% 是 **+10 个百分点**，相对提高 **20%**。不同 tokenizers、缓存命中率、输入/输出占比和促销期都会改变费用，单价不可脱离任务使用量。

### 成本应按“验收成功任务”计算

一次任务的总费用 = 未命中缓存输入 + 按实际规则计费的缓存写入/读取 + 思考与答案输出 + 搜索/抓取/沙箱等工具 + 失败重试 + 人工复核/返工。各平台思考 token 和缓存的计费归属不同，应按其具体账单规则归类，缓存写入的基础输入费等不重复计入。

每个成功任务成本 = **全部任务总费用 ÷ 验收成功数**。教学例：100 个任务共付模型费 20 元、工具费 5 元、人工 35 元，80 个合格，总费用 60 元，每成功任务 0.75 元；这不是“每次请求 0.20 元”能够表达的。没有做同样样本的实测前，不给出哪家真实最省的定论。AA 的任务成本方法也包含不同类型 token 与实际消耗，而非只比较标价。[方法说明](https://artificialanalysis.ai/methodology)

## 如何转化为你的日常行业研究能力

你要学的不是背型号，而是把每次发布变成一个可验证的假设。以下是一套可复做的评估设计，不是本报告已经跑完的实测。

| 任务 | 试题设计 | 验收与反证 |
| --- | --- | --- |
| 财报抽取 | 同时给两年年报、业绩说明、附注，含重述/单位变化 | 每个数有原页；归母/合并、期末/平均、币种一致；缺项留空 |
| 行业时间线 | 混入公告/生效/正式上市/修改四类日期与一份后续撤回公告 | 不把旧计划当现状；相互矛盾的版本有处理说明 |
| 多模态阅读 | 扫描表、跨页表、脚注、折线图、负值与括号 | 数字可回定位；图像/OCR错误不靠合理化填补 |
| 跨文件推理 | 合同、产能、销量、库存、财务口径分别放不同文件 | 结论链条可重算；识别口径不一致和替代解释 |
| 证据检索 | 设置官网、转引、过期稿和看似官方的非官方域名 | 实际读取正文；引用支持具体命题；未读到就承认 |
| 代码与数据 | 给缺失月份、重复行、负数、单位变更的 CSV | 修复不悄悄改数据；独立断言和核算；保留异常解释 |
| 可交付研究 | 先生成报告，再改一个假设并同步更新表图 | 图表/结论/数字一致；修改不破坏证据和其他章节 |

先建立 30–50 个代表性样本，再按模型快照、harness、工具、预算、成功率、引用准确率、p50/p95 完成时间、重试、人工分钟和总费用留档。样本量是建议，不是保证统计显著性的阈值。对缺失来源、无法核对的数字、关键引用不支持结论设阻断条件，避免漂亮文风掩盖事实错误。

初轮固定工具和预算比较模型；再分别优化每家框架，并将“固定环境下的模型增益”与“最佳产品组合增益”两张结果表分开。重要结论用新样本复核，别在同一批题上不断调提示词后仍称样本外测评。

## 接回 GPU、存储和产业链：研究假设与反证

以下是机制推导，**不是已经验证的订单预测或投资结论**。

| 技术变化 | 可能影响的产业链环节 | 需要跟踪什么 | 怎样推翻简单叙事 |
| --- | --- | --- | --- |
| 大 MoE、更多专家 | HBM/DRAM容量、卡间/节点间通信、网络和调度 | 总权重与精度、路由负载、专家并行、跨节点流量、利用率 | 激活少但通信/权重驻留仍大；总参大也未必同比增加每 token FLOPs |
| KV 压缩/线性注意力 | HBM带宽/容量、缓存层、SSD、推理服务软件 | 同长度/并发的 KV字节、TTFT、上下文质量和缓存命中 | KV少不等于整模型显存同比少；输入长度和并发反弹可能抵消节约 |
| n-gram/条件记忆卸载 | 主存容量/带宽、CPU、预取与互联 | 查表命中、CPU↔GPU流量、prefetch、尾时延 | 只看GPU计算削减而忽略主存/传输瓶颈 |
| QAT/低精度/投机解码 | 新精度计算单元、内存带宽、内核与推理框架 | 精度损失、草稿接受率、批量/负载、端到端吞吐 | 理论位宽或峰值TPS不能代表真实SLA；低负载和高负载收益不同 |
| 多Agent与长程任务 | 总token、沙箱、调度、网络、搜索/存储服务 | 全部子代理token、成功率、工具次数、关键路径、人工接管 | 并行提速可能增加总算力；更低单价能否刺激足够新增需求尚待验证 |

所以，“模型效率提高→算力需求一定下降”和“Agent更多→GPU需求必然按倍数增长”都缺少需求量、价格、利用率和瓶颈转移的中间证据。把节省后的单位成本与新增调用量分开建模，再用经营和实际部署数据检验。

## 证据边界与后续维护

1. 官方公告能证实其发布与宣称，不能自行证明所有能力或成本倍数。作者论文支持所述机制和实验条件，也不等于所有商业端点采用相同设置。
2. 权重仓库的初始提交可以包含真实分片；仍可能早于公开权限变化，因此本报告不把 commit 时间直接当首个公众下载时刻。仅有计划的权重日期保持为计划。
3. 持续更新的模型卡、价格页与 alias 是截至本次核验的快照。历史价格不以现价回填；开放许可证不跨家族一概而论。本报告不是逐条法律意见。
4. 日期仅核到月就保留月。地区/API/产品渠道不同时分别记录；未注明时区的公告保留原站日期，不擅自换算。
5. 新闻与第三方目录用于发现线索；与官方后续记录冲突时明确处理。未核的模型/日期、媒体专用支线和覆盖缺口保留在对应附录。
6. 未自行运行 benchmark、未下发付费调用、未取得各模型完整训练集，也没有据此声称排除了训练数据污染。报告不把未来路线图计入已发布事件。
