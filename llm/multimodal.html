先把三条不同的轴拆开

要问的问题能回答什么不能自动推断什么
输入怎样进入模型？视觉encoder、音频encoder、projector分别在哪？原始信号怎样变为可供语言骨干处理的向量有encoder不等于训练晚融合；没有独立大encoder也不等于视觉更强
多模态何时参与训练？只在文本预训练后连接，还是预训练早期就联合？模态对齐与知识共同学习的程度early fusion不等于删除所有模态专用部件
输出究竟是什么？文字、音频codec、图像/视频token，还是工具调用？模型本体能理解或生成哪种模态能看视频、能调用视频工具，不等于本体直接生成视频

最直接的反例是Qwen3.5官方卡 ↗：同时写明“early fusion training”和“Causal Language Model with Vision Encoder”。前者说训练策略，后者说结构，两者不矛盾。不能把“编码器+投影”和“早融合”硬画成互斥两派。

编码器+投影器：给语言骨干接入视觉，不是先把图全翻成文字

查看结构连接（文字版）
  • 图像 / 视频采样帧 → 视觉编码器 提取patch特征
  • 视觉编码器 提取patch特征 → 压缩 / patch merger 减少视觉token
  • 压缩 / patch merger 减少视觉token → 投影器 / adapter 映射到语言骨干维度
  • 文本 → 文本embedding
  • 投影器 / adapter 映射到语言骨干维度 → 交错多模态序列 保留空间 / 时间位置
  • 文本embedding → 交错多模态序列 保留空间 / 时间位置
  • 交错多模态序列 保留空间 / 时间位置 → 语言骨干 跨模态推理
  • 语言骨干 跨模态推理 → 文字回答 / 工具调用

教学上可把投影器看作维度转换：视觉特征为 V ∈ R^(Nv×dv)，线性投影近似 Z=VW ∈ R^(Nv×dmodel)；实际adapter可含MLP、attention或更复杂压缩。输出是连续向量，不必对应“猫”“金额”等人能直接读出的词。文本与视觉向量可进入同一骨干，但位置编码、mask、采样率仍可能不同。

代价主要来自视觉token数与信息压缩：高分辨率、多裁剪、多帧通常保留更多细节，也增加预填充计算、KV或循环状态处理以及服务延迟。过度压缩容易损失小字、相近符号和细粒度时间事件。模型的“能看”还应分成内容识别、文档结构、图表推理、空间定位、跨帧追踪来测。

这是通用教学抽象；Qwen3.8-Omni的原文确实列视觉编码器、普通AuT与Spatial AuT三条感知路径，再由adapter投影到Thinker共享空间；因此“统一表示”不意味着原始像素与波形直接共用文字分词器。Qwen3.8-Omni §2.1 ↗

统一理解与生成：以ERNIE5.0说明“统一”究竟统一了什么

查看结构连接（文字版）
  • 文本 / 图像 / 音频 / 视频 → 各模态tokenizer与表示提取
  • 各模态tokenizer与表示提取 → 统一序列表示
  • 统一序列表示 → 共享自回归MoE骨干 按表示路由到共享专家池
  • 共享自回归MoE骨干 按表示路由到共享专家池 → 文字：next-token
  • 共享自回归MoE骨干 按表示路由到共享专家池 → 视觉：下一尺度 / 下一帧token组
  • 共享自回归MoE骨干 按表示路由到共享专家池 → 音频：下一codec组
  • 视觉：下一尺度 / 下一帧token组 → 模态解码 / 重建
  • 音频：下一codec组 → 模态解码 / 重建

ERNIE5.0报告将文字NTP、视觉NFSP和音频NCP归入Next-Group-of-Tokens框架，并从头联合训练多模态。共享的是序列建模骨干与训练组织；图像生成可先粗尺度后细尺度、视频再沿时间预测帧。专家路由不靠预设“音频专用编号”硬分区，但专家仍可能从数据中学出模态偏好。ERNIE5.0 §2.1 ↗

这个例子也能反驳“统一模型没有专用模块”：报告的理解路径仍保留CNN+ViT双路特征和attention patch merger；生成路径使用量化token。理解更怕细节被压丢，生成还需保留可重建结构，两种需求没有因为统一骨干就消失。ERNIE5.0 §2.2 ↗

研究时看三件事：不同模态是否共享并更新骨干；理解与生成如何避免信息表示冲突；同等训练算力/数据下是否存在模态间性能牺牲。不能用公司自称“原生”代替这三个问题，也不能预设统一路线必然胜过模块化路线。

Thinker–Talker：流式理解与发声

Thinker–Talker：理解内容与实时发声分工

查看结构连接（文字版）
  • 画面 → Vision encoder
  • 声音 → AuT音频编码
  • Vision encoder → Thinker 理解 / 推理 / 产生文字
  • AuT音频编码 → Thinker 理解 / 推理 / 产生文字
  • 文字输入 → Thinker 理解 / 推理 / 产生文字
  • Thinker 理解 / 推理 / 产生文字 → 流式文字
  • Thinker 理解 / 推理 / 产生文字 → 音视频上下文特征
  • 流式文字 → Talker 文字与语音对齐
  • 音视频上下文特征 → Talker 文字与语音对齐
  • Talker 文字与语音对齐 → 当前音频帧的首码本
  • 当前音频帧的首码本 → 小MTP模块 补同帧残差码本
  • 小MTP模块 补同帧残差码本 → 因果Code2Wav
  • 因果Code2Wav → 可播放波形分片

“Thinker”是功能分工，不保证每次都执行显式长思维链；“Talker”也不是简单把一整篇已完成答案交给外部TTS。它可边接收文字与上下文、边生成语音。Qwen3系列已提供这条结构；2026年3.5-Omni进一步引入ARIA，把文字与语音单位自适应对齐后交错，缓解不同语言分词速度不匹配引起的漏词、读错数字和不自然韵律。Qwen3.5-Omni §2.1、2.5 ↗

音频码本可以类比一个80毫秒声音片段的分层描述：首层承载较粗语义，残差层补音色、韵律等声学细节。这里MTP补的是同一个时间帧的多个码本，不是先猜未来几个文字再由大模型拒绝采样验收。2026年Qwen3-TTS-12Hz采用12.5Hz、16层码本与轻量因果ConvNet，能单帧启动；25Hz版本则用单码本与分块DiT重建，不能把两种型号的结构混写。Qwen3-TTS §2、3.1 ↗

“流式”至少要拆输入分块、Thinker预填充、文字生成、Talker发声、客户端播放缓冲五段。因果Code2Wav只依赖左侧已知片段，少等待未来块，适合低首包延迟；代价是未来韵律信息更少，对对齐、停顿和长句自然度提出更高要求。这是因果性带来的工程取舍，不是声学质量自动无损。

Qwen3.8-Omni报告继续使用该路线，Talker增加24→48kHz重建，输入侧增加Spatial AuT保留多通道相位/幅度线索；这才是可以定位到部件的架构变化。Qwen-MM-Plugins、Live-Harness里的异步工具、子agent与长期记忆属于系统编排，不能画成MoE层内部新结构。Qwen3.8-Omni §2.1、7 ↗、开源Live-Harness ↗

指标需分开：首文字TTFT、首可播放音频延迟、稳态RTF、并发吞吐。Qwen3-TTS报告的97ms是0.6B、内部vLLM和编译优化等条件下的首包；不是语音提问完成到复杂问题答案的总时间。Qwen3.5-Omni表2还明说Plus和Flash资源分配不同，不能只横比235/435ms断言架构快慢。TTS效率实验 ↗、Omni效率表 ↗

代码核读：Transformers实现中TalkerCodePredictor在每步生成num_code_groups-1个残差码；Code2Wav使用因果卷积。这提供“码本层级，不是文本投机验收”的直接实现证据。Qwen团队/HF实现 ↗

OCR2：视觉表示与阅读顺序

DeepSeek-OCR2：先学着组织阅读顺序，再解码文字

查看结构连接（文字版）
  • 页面图像 → SAM-base + 卷积 压缩视觉patch
  • SAM-base + 卷积 压缩视觉patch → 视觉token V
  • 可学习flow queries Q → LLM式DeepEncoder V2 特殊attention mask
  • 视觉token V → LLM式DeepEncoder V2 特殊attention mask
  • LLM式DeepEncoder V2 特殊attention mask → 只取Q位置输出 语义重组后的视觉表示
  • 只取Q位置输出 语义重组后的视觉表示 → 文字MoE decoder
  • 文字提示 → 文字MoE decoder
  • 文字MoE decoder → Markdown / OCR文字与结构

要解决的不是“多看几次图”这个泛泛目标，而是双栏论文、表格、公式中空间先后和语义阅读顺序不一致。编码器中V可全局互看；Q_i可看所有V以及自身/之前的Q，不能看未来Q。可用下图理解mask，1代表能看：

         V1 V2 V3 | Q1 Q2 Q3
V1        1  1  1 |  0  0  0
V2        1  1  1 |  0  0  0
V3        1  1  1 |  0  0  0
-----------------------------
Q1        1  1  1 |  1  0  0
Q2        1  1  1 |  1  1  0
Q3        1  1  1 |  1  1  1

关键是连续特征的语义重组，不必真的输出一个硬排序数组；可学习queries也不是推理时先生成Q1再逐个生成Q2的文本循环。固定queries通过带因果mask的Transformer计算，最终只送其输出给文字decoder。论文称“两段一维因果结构”是在解释编码与解码的级联，不是已证明通用二维推理等同人类视觉。OCR2 §3.2 ↗

视觉预算保留256 + 144k，k=0…6，即256—1120个token；增加局部裁剪换取小字细节，同时增加算量。官方仓库明确默认全图1024²加最多6块768²，可据此复现预算。官方运行说明 ↗

反证不能省略：OmniDocBench中阅读顺序ED总体改善，但报纸文字ED从0.131到0.139变差，书籍也有退步；复杂内容高压缩不是免费午餐。生产日志无ground truth时只用重复率，不能把“重复少了”写成“所有文字准确率都提高”。论文§5.2—5.3 ↗
