# 中餐预制菜点单避雷

入口 `chinese-menu.html`，归入“日常研究”第三个专题。现有法国页和日料页均有入口。页面默认速查表，可切换详细卡片；按9类呈现94项菜品与点单场景，其中高66、中20、低8。单点肉菜与同款盖饭浇头分别记场景，不把94项当作94个无重叠菜名或市场样本。

## 判断与来源

资料读取日：2026-10-25。风险是编辑判断，不是实际门店使用率、概率、食品安全等级或厂家质量排名。依据包括：主要制作是否能外移、冷链和复热路径、成型半成品替代的备料劳动，以及已读取的供货资料。每项 `risk` 包含 `level`、`target`、`reason`；`ja` 在此数据中承载适用场景，导出列名通过 `ui.aliasLabel` 配置为“适用场景”。

本次5家厂家、31份来源记录，为56项关联直接或明确同类商品，其余38项明示工序推断。每份来源保留原页、用途范围、限制、读取日期和SHA-256。动态页面另记官网公开产品数据 `dataUrl`；哈希对应实际读取的HTML或JSON，不把只读页面框架当成已读商品资料。来源原页与数据入口均可在网页打开，导出也保留它们。

- **千味央厨**：具体产品页与官网分类数据。鱼香肉丝、台式卤肉、鲍鱼红烧肉、咖喱鸡与卤虎皮鸡爪明确写复热方式；四喜丸子、酿青椒、藕盒、茄盒、小酥肉、虾滑、春卷与糯米点心分别说明成型和最后熟制。小酥肉存在鸡肉和猪肉版本，不能只凭菜单名判断肉种。分类公开数据入口由原页脚本确认，正常读取 `/ajax/list2`。
- **安井食品**：官网“速冻菜肴制品”中安井小厨与冻品先生目录。通过正常展开分类确认公开数据菜单ID44、48，后读取分类数据。包含酸菜鱼、扇贝、扣肉、糖醋里脊、香酥带鱼、肥肠、鸡排与鸡米花等。目录证明商品供给，未据目录推定所有SKU的全熟状态。
- **聪厨**：官网首页及产品分类列出扣肉、外婆菜、小炒黄牛肉、剁椒鱼头、臭鳜鱼、拆骨肉、牛羊杂等。部分详情响应无正文，故用实际可读目录作菜名例证，未编造具体加热说明。
- **盖世食品**：蔬菜、菌菇、海洋珍味三类公开目录。例证包括爽口萝卜、油醋脆藕、藤椒豆腐丝、调味杏鲍菇、木耳、烤麸、鱼皮等。
- **凤祥食品**：调理鸡肉系列页及官网炒饭展示，范围含消费端同类商品。鸡米花和部分鸡排写有裹粉、浅炸速冻等工艺；狮子头例证是鸡肉版本，不能冒充全部猪肉狮子头。

搜索过程中返回无关内容的结果、验证码页、维护/错误页、只有空框架而没有商品正文的页面，以及无关行业的同名域名均未作为证据。味知香目录的具体菜名主要在图片中，本次未读取商品图文字，不以其“300+产品”企业介绍代替具体菜品证据。没有对任何门店作采购调查，也未据厂家销售范围推断全国使用比例。

## 适用边界

高风险优先看整菜或主要半成品，不靠出餐快、味浓、菜式多、最后冒烟等单独定性。例如：卤肉饭高风险主要指卤肉；酸菜鱼重点在鱼片与汤料；小酥肉主要看腌裹与预炸。白灼虾、清蒸整鱼、清炒菜等作为低风险对照，但仍不保证全部自制。

速冻面米、冷菜、外购普通豆腐、原料冷冻、净菜、基础调味品、中央厨房和门店自行提前备料有不同口径。这里是消费者广义外购供餐研究，不作法律上的预制菜认定。炖菜在门店批量自制并非外购；回锅肉的预煮本来就是工序，须问第一次煮肉的地点。专门现包、现杀、现熬的门店应按实际证据另判。

## 数据与交互维护

- `assets/chinese-menu-data.js`：`window.MenuRiskData`，包含菜品、风险、类别、来源和六组重灾区。新增记录必须写明场景、对象、理由；有商品参考再绑定相符来源，不能拿类似名称冒充完全一致的配方和工艺。
- `assets/washoku.js`：与日料共享只读引擎，中餐用 `ui` 配置导出名、列名、计量名和推荐菜。按用户要求移除餐饮专题中的收藏、私人笔记、填写区、文字搜索及下拉输入，使用分类、风险、路径和商品例证按钮筛选。推荐菜定位条件以文字显示，可点击“显示全部菜品”清除。
- 页面不含input、textarea、select或form，不读写收藏或笔记存储。速查表去除“留待点单”操作列，只保留菜品、风险和判断理由；移动端按行展示，保留表格标记与标题。其他研究页和IntelliUI的输入工具按用户明确范围保持可用。
- `assets/chinese-menu-risk.csv`：完整94项静态备份，更新菜品/风险/来源后运行 `python3 scripts/export_chinese_menu.py` 同步生成。表中保留商品入口、公开数据入口、编辑风险和场景。网页CSV仍导出当前筛选，并防止公式注入；餐饮专题不再提供私人笔记和Markdown导出。
