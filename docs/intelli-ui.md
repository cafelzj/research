# IntelliUI Beta

入口：`intelli.html`。这是一个在静态站点内运行的研究工作区，不需要后端、API 密钥或新的构建工具。

## 使用方式

从主导航进入 **IntelliUI BETA**。直接点击快捷操作，或输入“近6个月甲醇价格折线图”。支持折线图、柱状图、数据表、指标卡，支持“价格折线图，按品种区分不同颜色”“不同产品用不同颜色”等分色表达；折线图和柱状图以产品作为系列，每个产品具有稳定颜色（最多15种），支持一个产品或全部产品、一个数值指标、近1至120个自然月、全部月份或最新月份。时间范围以数据中的最新月份为基准，缺失月份不补值。

也可以展开“自己选择参数”，直接选择展示方式、产品、指标和时间。每张卡片支持独立修改、导出全部筛选记录、移除；清空、修改和数据切换支持最近10步撤销。最多8张卡片，避免无限增长。数据表最多预览100条，导出包含全部筛选记录。指标卡仅展示最新月份，不合计不同产品或月份。

CSV 使用共享的 `ChemData` 校验与会话存储，字段和产品选择随导入内容变化。导入新数据会清空当前卡片，可以撤销恢复原数据和卡片。数据明细与图表制作仍可读取完整导入数据，卡片筛选不覆盖它。工作区卡片仅在数据内容一致时恢复，避免把旧卡片误用于新数据。

数据与卡片留在当前浏览器标签页，关闭标签页后结束；撤销历史只保留在页面内存中。会话存储不可用时仍可使用，但会提示导出，刷新和跨页恢复不可依赖。

## 设计原则

采用意图驱动的工作区、可操作结果卡片、渐进展示参数、显式上下文和可撤销操作。无需通过对话反复描述细微修改；自然语言和表单最终生成相同的结构化计划。界面明确显示数据来源、月份、样本数和本地规则模式。

首版是规则解析，不是大模型。未识别的内容（例如“同比”）不会被静默忽略：先显示已识别的参数，用户确认后才生成。相互冲突的指标、展示方式或时间会被拒绝，保留已有工作区。不生成投资建议，也不伪造智能分析结论。

## 扩展卡片

`assets/intelli.js` 将指令解析、数据筛选、视图注册、工作区状态和导出分开。通过受控注册表增加视图，原有视图不需要修改。扩展脚本以 `defer` 加载，放在 `intelli.js` 之后；工作区在 DOMContentLoaded 时恢复，届时扩展已注册。使用可信的本地代码：

```js
window.IntelliUI.registerView('range', {
  label: '区间统计',
  aliases: ['区间统计'],
  render(container, plan, rows) {
    const values = rows.map(row => row[plan.field]);
    const text = document.createElement('p');
    text.textContent = `最小值 ${Math.min(...values)} / 最大值 ${Math.max(...values)}`;
    container.append(text);
  }
});
```

注册后，参数选择和自然语言解析自动发现该视图。`render` 接收卡片容器、只读计划和筛选数据副本。请使用 DOM API/textContent 呈现数据；不要把输入拼进 HTML、脚本或事件属性。内置图表采用本地 ECharts，卡片移除时释放实例，尺寸变化时统一重绘。扩展应保持同步、无额外持久副作用；额外的网络访问和资源清理需要单独设计。

计划格式：`{view, field, product, period}`。`product: '*'` 表示全部产品，`period: 0` 表示全部时间。`IntelliUI.resolvePlan(text)` 返回计划以及未识别内容或错误，`IntelliUI.addCard(plan)` 在校验字段、产品、视图和范围后添加卡片。任何输入都不能直接指定 JavaScript 或执行任意组件。

后续接入模型时，后端仅返回该结构化计划，并沿用字段、视图白名单和未知内容确认流程；模型密钥应放在后端。当前没有模型服务适配器，接入仍需实现服务端、超时/取消和错误处理。

## 本地验证

启动：`python3 -m http.server 8000 --bind 127.0.0.1`。

浏览器回归：`python3 scripts/test_intelli.py`，需要 Python Playwright 与 `/usr/bin/chromium`；测试针对本地静态服务，使用独立浏览器会话，不改动仓库数据。覆盖指令解析、图表、编辑撤销、CSV 与自定义字段、工作区恢复、导出、异常存储、手机宽度和主导航。

部署的文件列表在 `.github/workflows/pages.yml`，公网逐文件验证在 `scripts/verify_public_site.py`；两者均包含新入口。
