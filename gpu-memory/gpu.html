2. 一个 SM 就是一间精密数学车间

通用算术

FP32 / FP64 / INT32

浮点加减乘除、地址索引、整数操作、科学计算；负责广泛的非矩阵指令。

矩阵运算

Tensor Core

专用矩阵乘加数据通路，极大提高 AI 训练与推理的计算吞吐。

其他执行单元

SFU / Load-Store

特殊数学函数快速近似，以及数据加载存储等辅助计算操作。

Hopper 的 DPX 是一组特殊融合指令，不是必须单独计数的一排“DPX Core”。SM 还包括 Warp Scheduler、寄存器、共享内存和控制单元。[架构原文]

3. Tensor Core：矩阵乘法专用流水线

D = A × B + C

模型线性层、Attention 的 QKᵀ 和权重矩阵乘法，都会触发大量乘加。Tensor Core 不是只算一个乘法，而是把一块矩阵划成可高效执行的数据块，让线程协作计算。

示例：一个矩阵块

64 × 64 × 16

结果有 4096 个元素，每个元素需进行 16 次乘加，总共 65,536 次乘加。如果把乘法和加法分开计数，约 131,072 次浮点运算。

示例为数学工作量，不表示单个 Tensor Core 一周期完成全部工作。

加速关键

FP8 + 矩阵分块 + 数据复用

低精度输入降低存储与数据搬运需求；更高精度累加控制数值误差。Hopper 的 WGMMA 指令还支持线程组异步矩阵计算。

专家判断：Tensor Core 的理论峰值是上限；实际表现取决于矩阵形状、计算精度、数据复用、共享内存与 HBM 带宽。

4. SFU：为什么指数函数也需要专用硬件？

某些函数难以用一条简单加减乘除完成。GPU 用特殊函数通路加速指数、对数、倒数、倒数平方根以及部分三角函数的近似运算。

Softmax(xᵢ) = eˣⁱ / Σⱼeˣʲ
真实 AI 用途

Attention 的 Softmax

假设得分为 [2, 1, 0]，减去最大值后为 [0, -1, -2]；指数近似 [1, 0.368, 0.135]，归一化后约为 [0.665, 0.245, 0.090]。

SFU 加速其中的指数运算；归约求和、减最大值和最终缩放仍需要其他执行通路。

RMSNorm

先求均方，再计算倒数平方根以完成归一化；SFU 的 RSQ 指令有用。

Sigmoid 激活

σ(x)=1/(1+e⁻ˣ)，指数相关运算能够利用快速数学近似。

注意：特殊函数硬件通常提供近似值，高层数学库可能为精度、输入范围与异常处理执行多条指令。NVIDIA Hopper 详见 官方架构文档。

5. DPX：动态规划里的“加法 + 比较”融合

dᵢⱼ ← min(dᵢⱼ, dᵢₖ + dₖⱼ)

例如路径规划：从 A 到 C 直接成本 12，经过 B 为 5+4=9；算法需反复执行“先加法，再选最小值”。Hopper 的 DPX 指令可以将这类运算融合执行。

// CUDA 中与 Hopper DPX 对应的融合整数内置函数示意
int shortest = __viaddmin_s32(5, 4, 12);  // 9
int best = __viaddmax_s32(a, b, c);      // max(a+b, c)

另一个例子是 Smith–Waterman DNA 序列比对：每个动态规划格子需要对左、上、左上及零等候选值做加减和比较。

不要说 GPU 有一排 DPX 核心。 DPX 是 Hopper 支持的特定融合指令能力。单元计算更快，不代表动态规划完全解决了跨单元数据依赖和同步。

该图表示常见的数据层级，并非所有操作都必须依次穿过每一级。Hopper 的 TMA（张量内存加速器）可异步把多维数据块在全局内存和共享内存间搬运，有助于计算和数据传输重叠。

为什么 FlashAttention 有价值？

不是让 Tensor Core 的单次乘法更快，而是通过分块计算和在线 Softmax，让更多中间数据留在 SRAM 中，减少昂贵的 HBM 往返访问。

这体现了 GPU 专家常说的“数据流优化”：避免搬运往往比增加计算器数量更有效。

7. H200 耗电：计算与显存分别占多少？

没有一个适用于所有任务的固定比例。高负载矩阵运算、逐 Token 解码、空闲和大带宽访存测试的功耗构成均不同。

计算裸片

Tensor / CUDA / Cache / 控制器

计算单元开关切换、频率电压、缓存读写以及显存控制器的活动都会耗电。

HBM 存储堆栈

读写、刷新、层间通信

带宽压力高时，显存功率显著上升；但不能把显存高负载功率直接当成所有任务下的平均占比。

判断口径非常重要：H200 的 700W 是模组最高可配置功率；不能用“某次 HBM 读写测试功率 ÷ 700W”就声称那是同次实测显存占整卡功耗的百分比。需同步测量分部件电压轨功率和整卡总功率。

额外还要考虑 NVLink 收发、供电转换损耗，以及独立于 GPU 模组之外的服务器 CPU、网卡和冷却用电。

8. 从单卡到整机柜：为什么 NVLink 也重要？

单 GPU

算力、显存容量和 HBM 带宽决定单设备上限。

多 GPU NVLink 域

利用高速互连减少多卡并行时的数据通信瓶颈。

跨机柜集群

通过 InfiniBand 或以太网扩展，网络、调度和软件成为关键。

多 GPU 系统不等于所有 HBM 自动变成一块无延迟的共享内存。访问远端设备的数据有通信代价，推理吞吐还受到并行策略与 KV Cache 管理影响。
